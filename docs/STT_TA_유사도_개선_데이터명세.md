# STT/TA 유사도(TA_SCORE) 개선용 데이터 명세

> 목적: **정답지 문장(`SCRIPT_TA_SENT`) ↔ STT 발화 문장(`STT_SENT`) 유사도 점수(`TA_SCORE`) 산정 정확도 개선**
> 범위: 엔진이 **읽는 데이터(입력)** / **써야 하는 데이터(출력)** / **점수 규약** / **우리 측 정답지 정규화 규칙(STT 튜닝 기준)** / **정확도 저해 요인·개선 요청**

---

## 1. 핵심 개선 포인트 (한 줄 요약)

```
개선 대상 = TA_SCORE
= similarity( ms_script_sent.SCRIPT_TA_SENT ,  ms_stt_rslt.STT_SENT )
```

- `TA_SCORE`(유사도)는 후단에서 **문항 임계값(`QST_RATE`, 기본 60)** 과 비교되어, 넘으면 준수/못 넘으면 0점 처리됨 → **유사도 과소산정이 곧 점수 저조로 직결**.
- 우리 측 정답지(`SCRIPT_TA_SENT`)는 **5장의 정규화 규칙**을 거쳐 생성됨 → STT 측 문장 정규화를 이 기준에 맞추면 매칭률이 올라감.

## 2. 입력 데이터 (엔진이 읽는 값)

```

## 4. 점수 규약 (엔진 ↔ 우리 시스템 계약)

| 점수 | 스케일 | 산정 기준 | 후단 사용 |
|------|--------|-----------|-----------|
| `TA_SCORE` | **0 ~ 100** (유사도 %) | `SCRIPT_TA_SENT` ↔ `STT_SENT` 문장 유사도 | `TA_SCORE ≥ QST_RATE`(기본 60) → 준수 / 미만 → 0점 |
| `SCH_SCORE` | **0 또는 100** | `QST_KEYWORD`(공백 분리) 키워드가 STT 문장에 **전부 포함**되면 100 | 키워드형 문항 판정 |

**후단 환산(우리 배치, 참고)**: 키워드형이면 `SCH_SCORE=0→0점 / 100→TA_SCORE×배율`, 유사도형이면 `QST_RATE>TA_SCORE→0점 / else TA_SCORE`. 문항 0점 → 준수율 하락 → 최종 등급점수 하락.

## 5. 정답지(`SCRIPT_TA_SENT`) 정규화·분리·어미재결합 규칙 — ★ STT 문장 튜닝 기준

> 우리 측은 TM 스크립트 원문(`tb_sc_qst_mng.QST_CNTS`)을 아래 순서로 가공하여 `SCRIPT_TA_SENT`를 만듭니다.
> **STT 측이 이 규칙(구두점/기호 정규화, 문장 경계, 어미 처리)을 맞추면 유사도 매칭률이 올라갑니다.**
> 구현: `VrsParserWebAction.java`

### 5.1 [1단계] 태그·괄호·기호 정제 (적용 순서대로)
| 순서 | 처리 | 정규식 / 값 |
|------|------|-------------|
| 1 | HTML 태그 제거 | `<(/)?([a-zA-Z]*)(\s[a-zA-Z]*=[^>]*)?(\s)*(/)?>` |
| 2 | 꺾쇠 `<...>` 내부 제거 | `\<(.*?)>` |
| 3 | 대괄호 `[...]` 내부 제거 | `\[(.*?)]` |
| 4 | 소괄호 `(...)` 내부 제거 | `\((.*?)\)` |
| 5 | 변수 `$...$` 내부 제거 | `\$(.*?)\$` |
| 6 | 물음표 → 마침표 | `?` → `.` |
| 7 | URL 치환(마침표 오분리 방지) | `www.aig.co.kr` → `더블유더블유쩜에이아이지쩜씨오쩜케이알` |
| 8 | filter1 적용(공백치환 후 trim) | 아래 5.2 |
| 9 | filter2 적용 | 아래 5.3 |
| 10 | filter3 적용 | 아래 5.4 |

> 정제된 결과는 `ms_script_mng.QST_CNTS_P1` 에 저장됨. **filter1~3은 매칭된 부분을 공백(" ")으로 치환**하고 `trim` 함.

### 5.2 filter1 — 특수문자 (20개, 공백 치환)

(&nbsp;)|(&lt;)|(&gt;)|(,)|(-)|(\^\^)|(!)|(/)|(■)|(▶)|(◈)|(‘)|(’)|(“)|(”)|(•)|(\*)|(※)|(:)|(\")
```
| # | 대상 | | # | 대상 | | # | 대상 |
|---|------|--|---|------|--|---|------|
| 1 | `&nbsp;` | | 8 | `/` | | 15 | `”` |
| 2 | `&lt;` (`<`) | | 9 | `■` | | 16 | `•` |
| 3 | `&gt;` (`>`) | | 10 | `▶` | | 17 | `*` |
| 4 | `,` | | 11 | `◈` | | 18 | `※` |
| 5 | `-` | | 12 | `‘` | | 19 | `:` |
| 6 | `^^` | | 13 | `’` | | 20 | `"` (직선) |
| 7 | `!` | | 14 | `“` | | | |

### 5.3 filter2 — 넘버링·특약번호 (10개, 공백 치환)
```
(\d\))|(\d\d\))|(\d\.\s)|(특약[0-9]{2})|(특약[0-9]{1})|(특약 [0-9]{1})|(Yes\))|(No\))|(① 예)|(② 아니요)
```
| # | 대상(예) | # | 대상(예) |
|---|----------|---|----------|
| 1 | `1)` `2)` (숫자1+`)`) | 6 | `특약 1` |
| 2 | `10)` `12)` (숫자2+`)`) | 7 | `Yes)` |
| 3 | `1. ` `2. ` (숫자+`.`+공백) | 8 | `No)` |
| 4 | `특약01` (특약+2자리) | 9 | `① 예` |
| 5 | `특약1` (특약+1자리) | 10 | `② 아니요` |

### 5.4 filter3 — 고정 안내문구·선두 마침표 (11개, 공백 치환)
```
(or)|(변경된 내용 진행     필수 :)|(변경된 내용 진행  필수 :)|(추가된 내용 진행  필수 :)|(CT 검사비 언급시 필수멘트:)|(★ 치과  한의원  한방병원 언급시 필수멘트:)|(부담보조건부 인수스크립트 :)|(피보험자\))|(계약자 진행\))|(암진단비\))|(^[\.]*)
```
| # | 대상 | 비고 |
|---|------|------|
| 1 | `or` | |
| 2 | `변경된 내용 진행     필수 :` | 진행~필수 사이 공백 5칸 |
| 3 | `변경된 내용 진행  필수 :` | 공백 2칸 |
| 4 | `추가된 내용 진행  필수 :` | 공백 2칸 |

### 5.5 [2단계] 1차 문장 분리
정규식(`VrsParserWebAction.java`):
```
QST_CNTS_P1.split("(?!(?<=\\d)\\.)(\\.)|(시고)|(하며)");
```
- **마침표(`.`) 기준 분리** — 단, 숫자 뒤 마침표(소수점/날짜: `1.5%`, `2026.04.02`)는 제외
- 연결어미 **`시고`, `하며`** 위치에서도 분리
- 공백 제거 후 **1글자 이하 조각은 제외** (`length > 1`)

### 5.6 [3단계] 2차 어미 재결합
- 같은 `QST_CD` + `CNTR_CD` 내 **연속된 문장 조각**에서, 조각의 **마지막 글자**가 아래 연결어미면 다음 조각과 **공백으로 이어붙여** 한 문장으로 재결합:
  ```
  세, 는, 로, 의, 데, 시, 비, 금, 망, 당, 면, 후   (마지막 1글자 기준)
  ```
  
- 재결합 완료본이 `SCRIPT_TA_SENT`(분석용), 재결합 전 1차 분리본이 `SCRIPT_SENT`(표시용).

### 5.7 STT 측 튜닝 시사점 (요약)
- 정답지는 위 규칙으로 **괄호/태그/넘버링/특정 안내문구가 제거되고, 물음표가 마침표로 바뀌며, 마침표·`시고`·`하며` 기준으로 문장이 잘리고, 특정 연결어미로 끝나면 다음 문장과 재결합**된 상태임.
- 따라서 STT 문장도 **동일한 구두점/기호 정규화**와 **호환되는 문장 경계**로 만들면 표층 유사도 매칭이 유리함.
- 특히 정답지는 **한 문장이 완결형 어미로 끝나도록 재결합**되므로, STT가 발화를 과도하게 잘게 쪼개거나(=부분만 매칭) 반대로 너무 길게 뭉치면(=희석) 점수가 낮아짐.

### 5.8 숫자·단위 표기 규칙 — 숫자 vs 한글 (STT 출력 권장)

> `TA_SCORE`는 표층 문자열 유사도이므로 **정답지 표기와 STT 표기가 일치**해야 점수가 나옴. 혼용(정답지 숫자 ↔ STT 한글)이 최악.

**권장: 아라비아 숫자로 통일** (근거: 정답지가 숫자 중심)
- 1차 분리 정규식이 `숫자.숫자`(소수점/날짜 `1.5%`, `2026.04.02`)를 분리 예외로 보호 → 정답지에 **아라비아 숫자가 실제 존재**함을 시사.
- filter2가 `특약01`, `1. `, `숫자)` 등 숫자 표기를 다룸.

**세부 표기 규칙 (양측 통일 필요)**
| 항목 | 정답지 처리 | STT 권장 |
|------|-------------|----------|
| 천단위 콤마 `,` | filter1이 제거 (`30,000`→`30000`) | 콤마 없이 `30000` |
| 소수점 `.` | 유지 (`1.5`) | 그대로 `1.5` |
| 단위(원/세/개월/%) | 정답지 표기 따름 | 정답지와 동일 |
| 키워드형 문항 | `QST_KEYWORD`를 한글로 등록한 문항 존재 | 해당 문항은 한글이 유리 → 관리 표기 통일 |

**주의**: STT의 음성→숫자 변환 신뢰도가 낮으면(예: "삼만천원"→`30001` 오변환) 오히려 원음 한글이 안전할 수 있음. → **실제 정답지 표본으로 A/B 검증 후 확정** 권장.

## 6. 유사도 정확도 저해 요인 & 개선 요청

### 6.1 STT 문장 분리(경계) 품질 — 가장 큰 요인
- 현상: STT 원문이 **여러 문장이 긴 런온으로 뭉쳐** 내려오면, 짧은 정답지와 비교 시 유사도가 전체 길이에 희석되어 임계값 미달.
- 예: 정답지 `가입에 동의하세요` ↔ STT `상품 보험료 삼만천원 … 가입에 동의하시죠? … 감사합니다`(한 문장) → 부분 일치임에도 저점수.
- 요청: ① **문장 경계 분할 정확도 개선**, 또는 ② **부분 구간(최적 매칭) 유사도**(긴 STT 문장 내에서 정답지와 가장 유사한 구간을 찾아 점수화).

### 6.2 어미/문형 차이
- `동의하시죠?`(의문형) ↔ `동의하세요`(평서형)처럼 의미 동일·어미만 다른 경우 감점.
- 요청: **어미 정규화 / 형태소·의미 기반 유사도** 반영.
